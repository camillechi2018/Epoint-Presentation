# 正文组件与公共页眉解耦实施计划书

版本：v1.0；日期：2026-11-12；状态：计划已编制，分支已隔离，功能实施待启动。

## 1. 目标与实施原则

从知识库正文页归纳页标题、Logo 和公共装饰的形态，沉淀为技能管理的公共页面框架；知识库提供可独立填充的正文组件。生成时按内容选择正文组件，再与兼容的页面框架组合，使页标题不再受到各正文模板不同字段上限的牵制。

开发、试点和优化均在独立分支与工作目录完成，达到本计划的稳定条件后再合并 main。当前交付限于计划和分支准备；本文件中所有新接口、文件名和阶段产物均为拟议设计，不能视为已有功能。

核心原则：

- 保持材料事实完整、原生对象可编辑、组件图形关系正确。
- 技能管理页标题、Logo、公共装饰、画布和安全区；知识库管理正文图形及其字段、几何和能力记录。
- 普通正文按结构匹配；专用语义、真实项数、图表数据和正文容量约束继续有效。
- 保留来源整页，生成可追溯的正文派生组件；不通过裁图或遮挡旧标题来完成拆分。
- 封面、目录、章节、封底继续走专用整页模板流程。
- 同一稿统一主题和默认页眉；确需使用兼容变体时记录原因，避免逐页随机更换。

## 2. 当前基线与已发现规律

现有 `assets/layouts/offline-core.json` 已包含简约公共页眉与科技风公共页眉，但主要服务技能排版和自由编排。科技风资产源于 `content-tech-021` 的右上 Logo 形态。新方案应扩展这一基础，并验证多数原页采用的右下 Logo 形态，不直接将现有资产视为全库通用框架。

## 3. 职责与模块边界

| 模块 | 负责内容 | 不得混入的内容 |
| --- | --- | --- |
| 技能公共框架 | 页标题框、字体层级、Logo 原件及位置、公共装饰、画布、正文安全区、容量与碰撞检查 | 模板业务文字、正文组件列表及逐组件容量副本 |
| 知识库正文组件 | 原生形状、图表、表格、条目标题、正文、内部中心标题、必要局部装饰 | 已剥离的公共页标题必填项、重复 Logo |
| 知识库兼容元数据 | 来源、删除对象定位、保留对象、正文边界、框架兼容条件、变换范围、例外和验收证据 | 通过任意缩放或删字实现的适配声明 |
| 装配与审计 | 选框架、填正文、组合、来源追踪、最终渲染检查 | 把召回成功算作实际复用，把程序成功算作视觉验收 |

“自由匹配”定义为在已验证的风格、画布、正文安全区和组件能力范围内组合。跨主题换色、任意缩放、变更项数或图形语义不因本次解耦自动开放。

## 4. 技术方案

### 4.1 公共框架登记

拟在技能中建立版本化框架登记，复用现有品牌资产与布局基础，避免维护两套互相矛盾的默认值。拟议字段：`frame_id`、`frame_version`、`theme`、`style_family`、`canvas`、`title_variants`、`logo_asset`、`logo_box`、`body_safe_regions`、`reserved_regions`、`font_profile`、`source_reference`。

第一批建立简约和科技两个框架族。标题宽窄与 Logo 位置作为受约束变体，不机械生成所有排列组合。选择优先级：用户明确指定且兼容的变体 → 整稿默认变体 → 同族已验证替代变体；没有兼容项时返回具体原因。

标题容量按实际字体、字号、行数、文本宽度和安全区计算，再通过目标应用渲染确认。不得新设一个全局“最多 11 字”替代所有原限制。短、边界、长标题及中英数字混排分别验收；过长时优先使用已验证加宽或双行变体，仍不适配则报告。双行变体在验证前不开放；不得自动删字或无限缩小字体。

### 4.2 正文组件拆分

逐页辨认：公共标题、Logo、公共装饰、正文对象、内部标题和无法独立拆分对象。对象定位必须包含源文件/页面、对象 ID 与组路径；母版及版式对象单独登记，避免重名或组内 ID 误删。

拟为组件增加 `body_component_contract`，记录来源哈希、提取版本、保留/移除对象、正文边界、原坐标、兼容框架条件、允许变换、状态和证据路径。图表、工作簿、图片、SVG 回退、母版和主题依赖随实际保留对象迁移。

优先保留原生坐标，仅对登记允许的组件进行平移或等比例缩放；变换后重新验证字号、线宽、图标、连接线与可编辑性。背景图已烘焙标题或 Logo、顶部与正文难以拆分的页面进入例外队列，保留整页能力，不冒充已解耦组件。

源组件 ID 保持稳定，通过派生版本区分正文资产，保留旧整页路径。原记录中的公共页标题绑定只在新版正文契约中退出必填；内部 `heading`、`section.title`、`items[i].title` 等依真实语义保留。不能全局删除带 title/heading/label 的字段。

### 4.3 选版、填充与组装

新路径：锁定主题与字体 → 读取独立页标题 → 按正文关系、项数和字段选组件 → 校验正文容量 → 选兼容框架 → 填充正文 → 添加公共框架 → 组装 → 审计与视觉验收。

候选发现阶段不再拿公共页标题长度筛掉正文组件；正文自身必填字段和容量照常检查。页标题的匹配与失败原因单独记录。已有请求中的标题字段通过明确映射兼容，若同时提供新旧字段且内容冲突，应报告而非静默覆盖。

默认可先以原生单页副本删除登记公共对象、再插入技能框架，减少跨页对象复制风险；最终采用这一方式还是独立正文资产，由试点对包关系、背景依赖和编辑效果的验证决定。禁止用白色遮盖块隐藏旧标题或 Logo。

每页记录正文来源提交/哈希、组件派生版本、框架 ID/版本、实际变换及失败重试。新增正文组件复用类型时同步调整来源审计，不把“技能提供页眉”误算为整页自由编排。

### 4.4 新旧兼容与离线

新知识库先以增量字段和派生资产上线，旧整页资产继续有效；技能通过契约版本与能力声明选择新路径。旧技能读取新知识库时仍可使用旧整页，新技能读取旧知识库时使用旧路径并记录尚未解耦。未知必需契约版本明确阻断该组件，不猜测处理。

开发期通过显式实验开关启用新路径，默认路径待验收后切换。调用固定知识库提交，不在同一稿中混用不同版本。离线完整缓存需包含匹配的派生资产；最小包缺正文时继续明确报告候选范围，不能声称正文组件已离线齐备。

发布阶段统一生成技能与知识库清单，验证 Git 归档、LF/CRLF 检出、完整缓存与最小包。运行期不重写哈希绕过校验。

## 7. 验收与稳定定义

### 7.1 功能、内容和视觉

- 同一正文组件能配合至少两种已登记兼容标题变体；同一公共框架能配合不同结构正文组件，证明已解耦。
- 页标题变长不会触发正文组件旧 page.title 字段限制；新公共框架仍按实际容量拒绝真正溢出的标题。
- 所有自动开放组件均有单页填充、包检查、渲染和人工视觉记录；没有重复页标题/Logo、源稿示例文字残留或未登记遮挡。
- 对所测样本，标题、Logo 与正文无未处理碰撞，Logo 形态与可见尺寸正确，所有输入事实都有去向。
- 保持可编辑文本、形状、图表、表格及关联数据；拆分后的连接关系、层级和主题颜色符合预期。
- 缺内部中心标题、错误项数、严格语义不符、图表数据不足、标题过长及正文超过容量的负例仍正确拒绝。
- 封面、目录、章节、封底的来源、顺序、统一章节版式和品牌检查无退化。

### 7.2 回归矩阵

| 维度 | 必测内容 | 证据 |
| --- | --- | --- |
| 主题 | 蓝、红、科技 | 各框架及 Logo 变体对照图 |
| 文本 | 短标题、边界标题、长标题、中英数字、换行；正文短/长 | 输入、实际字号/行数、渲染结果 |
| 对象 | 普通形状、组合、母版依赖、图表、表格、SVG | 原生编辑抽查及包审计 |
| 版本 | 新技能×新库、新技能×旧库、旧技能×兼容新库 | 配对提交与执行报告 |
| 网络 | 在线固定提交、已验证完整缓存、仅最小包、哈希损坏 | 来源标记和准确失败原因 |
| 系统 | Windows 正式路径、Linux 已支持路径、Mac 已支持/实验路径 | 本机实际证据，实验能力仍按原边界标注 |
| 材料 | 沈阳文档蓝色主验；原有三材料×三风格回归 | 同事实基线下的新旧整稿与指标 |

本机不能替代 Mac 实机视觉验收；实施时复用跨系统任务的环境与测试入口。Mac 未完成的结果明确标记待验收，不扩大跨平台支持声明。任何已正式支持平台被此改动影响，都需补齐该平台验收后方可正式启用。

### 7.3 指标口径

分别记录：已迁移组件数/冻结范围数；实际正文组件填充成功页数/正文总页数；知识库组件正确承载的事实单元/固定事实单元；页标题耦合导致的拒绝次数；各类 fallback 原因；最终视觉通过页数。

技能页眉不计入正文组件复用分子，蓝红变体不重复计结构，召回与试填成功分开。目标是消除已迁移组件的旧页标题限制误拒绝，材料事实覆盖不下降。复用率提升幅度在 S0 基线后测量，不预先保证固定百分比。

### 7.4 合并 main 的必要条件

1. S0–S4 的阶段记录齐全；每项实际通过、例外或待验收可查。
2. 已开放新路径没有事实丢失、文件损坏、原生对象破坏、品牌错误、可见碰撞等阻断问题；所有例外明确关闭新路径或修复。
3. 最终配对候选完成一次完整矩阵；缺陷修复后重测受影响项，并使用干净目录重复关键端到端流程，结果一致。
4. 保留原正文长文案与结构语义验收；字体、几何、容量或换行受影响的组件补测，不直接继承为已通过。
5. 同步最新 main 后，针对冲突和依赖变化复验；清单、归档与安装路径通过，回退验证完成。
6. 具有实际渲染和逐页视觉复核记录；`ready`、程序退出成功或 ZIP 可解压都不替代交付验收。

## 8. 工作量与风险安排

实施前估算为 8–14 个有效工作日：基线及规范 1–2 日、试点与执行器 2–3 日、批量迁移及例外 2–4 日、整稿/兼容回归 2–3 日、发布稳定 1–2 日。该估算不包含等待另一项任务合并和 Mac 实机反馈的时间；S2 完成后按真实自动提取成功率重新估算，不能视为交付承诺。

主要成本在对象识别、背景/母版依赖、逐页视觉验收和兼容发布，公共页眉绘制本身只占部分工作。Token 随例外数量、日志长度和修复轮次变化，本计划不将固定 token 数作为完成或合并门槛；执行时按阶段记录实际使用量（平台可提供时）。

| 风险 | 处理方式 |
| --- | --- |
| 误删内部标题 | 语义与对象定位双重核对；两个科技 heading 作为固定负例 |
| 宽标题侵入 Logo 区 | 使用实测净空选择变体；宽度不同不等于可以无条件加宽 |
| 背景烘焙标题或 Logo | 登记整页例外，另做可编辑重构评估 |
| 新框架压缩正文 | 安全区兼容筛选；允许变换须重新渲染，不统一缩小全部正文 |
| 与跨系统修改冲突 | 等待其稳定基线；隔离开发，冲突后复验公共入口 |
| 清单或版本错配 | 配对版本、兼容声明、发布期清单生成、运行期严格校验 |

## 9. 回退与最终交付

实验期关闭新路径即可回到旧整页流程。正式发布保留上一配对版本、旧整页资产和必要缓存；出现问题时先停用受影响组件的新能力，必要时回退技能和知识库配对版本。禁止以删除共享缓存、强制改写 main 历史作为常规回退。

最终交付包括：本计划的修订版、形态图册与可编辑样页、版本化框架登记、正文组件契约及派生资产、完整迁移台账、真实材料示范稿、测试与视觉记录、版本兼容矩阵、发布和回退说明。实施进度随阶段更新，未执行项目不得标成已完成。
