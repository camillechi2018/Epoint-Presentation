# 材料结构化与正文选稿

材料读取产出的段落、表格和来源清单由当前 Agent 组织成逐页草稿。正式选版、单独整理和匹配审计默认自动提取正文匹配字段。整理程序使用草稿的原段、来源、已有信息关系和图片，运行时无需用户逐页标注，也无需额外模型服务。

## Agent 必须完成的整理

1. 从事实清单辨认真实条目、说明、指标数值/单位/时期、步骤顺序及引用来源；保留否定、约数、计划/已完成状态等限定条件。
2. 先选择内容关系，再组织字段：普通并列用 cards 的 title/body；指标、表格、流程等使用现有对应输入类型，不把所有材料统一写成 bullets。只在材料确有关系时选择流程、层级或循环。
3. 并列原文可先以字符串列表提供。技能提取能用原文核对的短标题，固定一对一映射。在请求已经明确给出 `content.item_titles` 或 `body_match` 时沿用这些字段。
4. 根据候选容量再确定分组和分页；不得为固定项数凭空拆成更多业务点。暂时放不下时保留事实，换版或拆页。本轮准备工具不压缩正文、不改项数、不使可选字段失效。

## 自动整理范围

| 逐页草稿关系 | 自动匹配字段 | 核对条件 |
| --- | --- | --- |
| 并列要点 | 每段一个原文短语作为标题 | 正文逐条保留、顺序一致、标题可定位到同一段。 |
| 指标、数据 | 原段内相邻的指标名称和完整数值，可选明确时段 | 保留数值符号、单位、限定语和全部原段。主次含混时保留原有正文结构。 |
| 层级、单论点 | 由语义证据定位分组或主论点 | 层级按原段顺序完整覆盖，单论点来自可唯一识别的原段。 |
| 表格 | 原段题签和两列表头 | 原有摘要形成一行一段的原生表格，金额、公式文字和口径沿用原文。 |
| 图文 | 已有四图或五图的原图与图注 | 保留图片、相邻图注及原顺序。 |

`content_preparation.automatic_pages` 记录自动生成的页面匹配字段和来源。自动字段写在页面级的 `body_match`。组装仍以原 `content` 作为回退，遇到证据不足或不适配组件时可继续使用。自动规则从已组织的原始逐页草稿开始，原件读取和分页仍按材料接入流程执行。

## 内容准备入口

```text
<Python> scripts/run.py --structure-content --request <逐页草稿.json> --out <整理后请求.json> --report <整理报告.json>
```

使用安装器登记的解释器，与材料读取和选稿入口一致。输出路径必须为新文件，不能覆盖源请求。

并列条目的最小示例（仅展示正文页，结构页仍按原规范准备）：

```json
{
  "theme": "blue",
  "complete_deck": false,
  "pages": [{
    "page_id": "overview",
    "role": "body",
    "purpose": "介绍项目情况",
    "title": "项目情况",
    "information_relation": "parallel-points",
    "source_refs": ["本次事实清单中的真实来源引用"],
    "content": {
      "type": "bullets",
      "items": ["约200人参与，计划2027年部署。", "目前尚未通过验收。"],
      "item_titles": ["人员与计划", "验收状态"]
    }
  }]
}
```

工具输出 `cards`，每项含 title 和逐字保留的 body，并保留页面来源及字段转换记录。已是结构化 cards/metrics/process/table 等输入直接沿用，仍由对应选稿与填充规则验证；准备步骤不宣称已经完成全部业务校验。

已有 `cards` 也要逐项检查小标题。若标题是从正文机械截取的半句话（例如停在数字、小数或未完的词组），应由当前 Agent 依据同项原文重新概括为完整短语，再按候选槽位容量提交；正文和数字保持原事实。字段试填通过不代表这类标题已经达到视觉交付质量。

自动整理和现有标注均无法形成可靠结构时，单独整理命令返回 `needs_agent_structure` 和具体 `tasks`，仍写出保全原文的草稿，退出码为 2。正式出稿按原结构继续，无法确认的流程、闭环或上下级关系保留原有表达。

法律条款、原文摘录等确实适合逐条展示时，允许在 content 中填写 `keep_bullets_reason`，例如“逐条保留原始条款措辞”；工具保留 bullets 并记录理由。无需为追求模板率强行卡片化。

报告 `ready_for_matching` 只表示没有此步骤的待办。接下来运行常规 `scripts/run.py --request ... --plan-out ... --out ...`；字段齐全、容量合格、实际填充、最终渲染各有独立检查。

## 旧请求兼容

已有 `item_titles` 的并列列表继续按原流程规范化。设置请求级 `auto_structure: false` 可关闭自动推断，保留已有标注的原有处理方式。准备程序按既有业务语义约束、绑定容量和模板验收状态执行。

## 与页标题/Logo 解耦的关系

材料结构化负责“内容是什么、各条信息是什么关系、正文如何分组”；公共页眉解耦负责“页标题和 Logo 放在哪里、由哪个框架管理”。两者都帮助组件复用，但职责不同。

正文内部的小标题、中心论点和字段属于组件内容。页面顶部标题和 Logo 属于公共框架。匹配输入可试填知识库纯正文组件，公共页眉由技能按实际主题装配。
